# Architecture - Phase 2
Input UTF-8 text -> input validation -> selected detector -> deterministic overlap handling -> validated original Unicode code-point spans -> reverse-order replacement -> JSON or Gradio outputs.

- Regex: original src/piiparity/core.py is unchanged from Phase 1 (Git blob aaba090a2f6167742191d21386e4dc326f40eac9). Recognizes ASCII email and plus-prefixed phone formats. No model needed for CLI Regex mode.
- AI: ai.py lazily loads pinned local GLiNER once, uses CPU inference under a lock, and returns all four requested categories when predicted above 0.5. Tokenization adapts script boundaries without rewriting text. No hosted inference endpoint.
- Hybrid: combines regex and AI candidates. Structured regex spans win overlaps; remaining candidates rank by descending raw score, descending length, ascending start and alphabetical label. Greedy selection produces disjoint spans. Entire losing candidates are discarded (including any non-overlapping tail), so inspect dropped_overlaps and do not assume maximal coverage.

Each entity has label, original start/end, extracted original text, source, and score (null for regex). Highlight chunks reconstruct the input exactly; redaction replaces only selected spans. Any detection error can still leave PII or remove non-PII. Model exceptions do not silently produce a regex result labeled as AI.

Gradio runs on 127.0.0.1:7860, share=False, with analytics disabled, no cached examples, input database or application text logging. Requests reside transiently in local server/browser memory. It computes AI once and derives Regex/AI/Hybrid comparisons, then shows the selected output. Thus UI comparisons require model assets even when Regex is selected; standalone Regex CLI remains available without them. Language selection labels results only; there is no automatic language detector or translation. Gradio assets/fonts and package startup may involve framework network behavior; no user text is sent to a hosted model. HF inference is configured offline and ONNX Runtime telemetry is explicitly disabled after import.

Data flow for evidence: frozen original smoke JSONL -> unchanged metric formulas with a pluggable detector -> diagnostic reports, split by language/label, containing prediction and gold examples. Tests use constructed predictions for pure integration cases; experiments/phase2_smoke.py and experiments/verify_ui.py run the actual model. No training or independent benchmark is performed in Phase 2.
